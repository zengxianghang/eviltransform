# WGS84 与 GCJ-02 坐标转换技术说明（以 eviltransform 为例）

## 1. 背景

GNSS 接收机通常输出 WGS84 坐标，而中国大陆互联网地图通常使用 GCJ-02 坐标。两者之间存在几十米到数百米的位置偏移。

本文以 `eviltransform` 为例，介绍 GCJ-02 转换的来源、实现方式、计算量和误差特点。

---

# 2. 是否存在官方公开转换方式？

目前没有公开发布的 GCJ-02 官方数学转换规范。

公开信息只能确认：

- 中国大陆互联网地图需要使用经过处理的坐标体系；
- GCJ-02 被大量地图服务采用；
- 地图厂商提供坐标转换服务。

但是没有公开：

- GCJ-02 完整数学公式；
- 参数定义；
- 官方源代码。

因此：

```
GCJ02 = F(WGS84)
```

中的函数 F 并不是公开标准。

---

# 3. 为什么没有官方转换方式？

GCJ-02 的目的不是建立新的测量参考框架，而是对互联网地图数据进行位置扰动处理。

如果公开：

```
GCJ02 = F(WGS84)
```

则可以进一步求逆：

```
WGS84 = F^-1(GCJ02)
```

恢复原始坐标，因此没有公开完整算法。

---

# 4. 开源仓库如何实现？

由于没有公开公式，开源项目通过大量样本分析得到事实兼容模型。

`eviltransform` 使用：

```
GCJ02 = WGS84 + offset(WGS84)
```

其中：

```
dLat = f(lat, lon)
dLng = g(lat, lon)
```

主要函数：

- `transform()`：计算空间扰动；
- `delta()`：完成椭球修正；
- `wgs2gcj()`：正向转换；
- `gcj2wgs()`：快速逆转换；
- `gcj2wgs_exact()`：搜索求逆。

---

# 5. eviltransform 正向转换计算量分析

一次 `wgs2gcj()` 调用主要经过：

```
wgs2gcj()
 |
 |-- outOfChina()
 |
 |-- delta()
      |
      |-- transform()
      |
      |-- ellipse correction
```

## 5.1 transform() 中的数学调用量

以当前 C 实现为例：

### sin() 调用

`transform()` 包含：

纬度方向：

```
sin(6*x*pi)
sin(2*x*pi)
sin(y*pi)
sin(y*pi/3)
sin(y*pi/12)
sin(y*pi/30)
```

经度方向：

```
sin(6*x*pi)
sin(2*x*pi)
sin(x*pi)
sin(x*pi/3)
sin(x*pi/12)
sin(x*pi/30)
```

其中前两个公共项只计算一次。

因此：

```
sin() = 10 次
```

左右。

### cos() 调用

`delta()` 椭球修正：

```
cos(radLat)
```

因此：

```
cos() = 1 次
```

### sqrt() 调用

主要来自：

`transform()`：

```
sqrt(abs(x))
```

`delta()`：

```
sqrt(magic)
```

因此：

```
sqrt() = 2 次
```

---

## 5.2 其他浮点运算

除三角函数外，还包含：

- 加减运算：几十次；
- 乘法：几十次；
- 除法：数次。

算法复杂度：

```
O(1)
```

---

# 6. 逆转换计算量

## 6.1 快速逆转换

`gcj2wgs()`：

```
WGS ~= GCJ - offset(GCJ)
```

计算量约等于一次：

```
wgs2gcj()
```

即约：

```
sin() 10 次
cos() 1 次
sqrt() 2 次
```

---

## 6.2 高精度逆转换

`gcj2wgs_exact()` 使用搜索方法。

每次迭代需要调用：

```
wgs2gcj()
```

例如最多 30 次：

```
sin() ≈ 300 次
cos() ≈ 30 次
sqrt() ≈ 60 次
```

因此计算量约为快速逆转换的几十倍。

---

# 7. 转换误差分析

## 7.1 WGS84 与 GCJ-02 本身偏移

典型：

```
几十米 ~ 数百米
```

这是 GCJ-02 的设计结果，不是转换错误。

---

## 7.2 不同开源实现差异

由于没有官方公式，不同实现可能存在：

- 椭球参数差异；
- 边界判断差异；
- 逆转换策略差异。

通常：

```
厘米级 ~ 米级
```

---

## 7.3 eviltransform 逆转换误差

根据项目说明：

- `gcj2wgs()`：约米级误差；
- `gcj2wgs_exact()`：亚米级。

---

# 8. GNSS 工程建议

GCJ-02 不应参与高精度定位计算。

推荐：

```
GNSS
 |
WGS84 / CGCS2000
 |
ECEF / ENU
 |
Position analysis
```

地图显示：

```
WGS84
 |
GCJ02
 |
Map
```

---

# 9. 总结

|项目|说明|
|-|-|
|官方转换公式|未公开|
|开源实现|基于逆向分析形成事实标准|
|正向转换计算量|约 sin 10 次、cos 1 次、sqrt 2 次|
|快速逆转换|约一次正向转换计算量|
|精确逆转换|约几十次正向转换计算量|
|坐标偏移|百米级|
|实现间差异|厘米到米级|

`eviltransform` 是当前广泛使用的 GCJ-02 兼容实现之一，适用于地图显示和 GIS 转换，但不适合作为 GNSS 高精度定位参考坐标。
