# WGS84 与 GCJ-02 坐标转换技术说明（以 eviltransform 为例）

## 1. 背景

GNSS 接收机通常输出 WGS84 坐标，而中国大陆互联网地图服务通常使用 GCJ-02 坐标。两者之间存在几十米到数百米的位置偏移。

典型流程：

```
GNSS Receiver
      |
      v
    WGS84
      |
      | coordinate transformation
      v
    GCJ-02
      |
      v
 Internet Map Service
```

本文件以 `eviltransform` 项目为例，介绍 GCJ-02 转换的实现原理、计算量和误差特点。

`eviltransform` 是一个开源坐标转换库，实现了 WGS-84 与 GCJ-02 的双向转换，并提供快速逆转换和高精度逆转换接口。

---

# 2. 是否存在官方公开转换方式？

## 2.1 结论

目前没有公开的 GCJ-02 官方数学转换规范。

公开资料中可以确认：

- 中国大陆互联网地图需要采用经过处理的坐标体系；
- GCJ-02 被大量地图服务采用；
- 地图厂商提供坐标转换 API。

但是没有公开：

- GCJ-02 数学公式；
- 转换参数；
- 官方源代码。

因此：

```
GCJ02 = F(WGS84)
```

中的 F 并不是公开标准。

---

# 3. 为什么没有官方转换方式？

## 3.1 GCJ-02 的目的不同

WGS84 是全球卫星导航参考框架，用于：

- GPS
- BDS
- RTK
- PPP
- 测量

而 GCJ-02 主要用于互联网地图显示。

它的目标不是提高测量精度，而是对公开地图数据进行位置扰动处理。

---

## 3.2 公开公式会降低扰动效果

如果公开：

```
GCJ02 = F(WGS84)
```

则可以通过求逆：

```
WGS84 = F^-1(GCJ02)
```

恢复原始坐标。

因此官方没有公开完整转换算法。

---

# 4. 开源仓库如何实现转换？

由于 GCJ-02 没有公开公式，开源项目通过大量样本和已有地图行为进行逆向分析，形成事实上的兼容实现。

`eviltransform` 使用典型模型：

```
GCJ02 = WGS84 + offset(WGS84)
```

其中：

```
dLat = f(latitude, longitude)
dLon = g(latitude, longitude)
```

---

# 5. eviltransform 正向转换流程

## WGS84 -> GCJ02

流程：

```
WGS84
 |
 | outOfChina()
 |
 | transform()
 |
 | delta()
 v
GCJ02
```

主要步骤：

## 5.1 区域判断

GCJ-02 主要用于中国大陆区域。

超出范围时直接返回原坐标：

```
GCJ02 = WGS84
```

---

## 5.2 扰动计算

`transform()` 使用：

- 多项式项；
- 正弦周期项；
- 非线性空间扰动。

例如：

```
sin()
cos()
sqrt()
```

生成连续变化的偏移场。

---

## 5.3 椭球修正

扰动结果需要根据地球椭球参数转换为经纬度偏移。

使用：

- Earth radius
- eccentricity

最终：

```
gcjLat = wgsLat + dLat
gcjLng = wgsLng + dLng
```

---

# 6. GCJ02 -> WGS84

由于：

```
GCJ02 = F(WGS84)
```

不存在公开解析逆函数。

因此开源实现通常采用近似或搜索方法。

---

## 6.1 快速逆转换

`eviltransform` 的 `gcj2wgs()`：

```
WGS ~= GCJ - offset(GCJ)
```

优点：

- 速度快；
- 实现简单。

缺点：

- 存在米级误差。

---

## 6.2 高精度逆转换

`gcj2wgs_exact()` 使用搜索方法：

```
Guess WGS84
      |
      v
WGS84 -> GCJ02
      |
      v
Compare error
      |
      v
Shrink search range
      |
      v
Repeat
```

通过不断缩小搜索范围，使正向转换结果逼近目标 GCJ-02 坐标。

---

# 7. 运算量分析

## 7.1 WGS84 -> GCJ02

一次转换主要包含：

- 多次 sin/cos；
- sqrt；
- 浮点乘加。

复杂度：

```
O(1)
```

普通 PC 上通常为微秒级。

嵌入式平台取决于数学库实现，一般为几十到几百微秒。

---

## 7.2 快速逆转换

计算量约等于一次正向转换。

---

## 7.3 高精度逆转换

需要多次调用正向转换。

例如 30 次搜索：

```
Cost ~= 30 * WGS84->GCJ02
```

精度更高，但速度更慢。

---

# 8. 转换误差分析

## 8.1 WGS84 与 GCJ02 本身的偏移

典型：

```
几十米 ~ 数百米
```

这是 GCJ-02 的设计特点，不是转换错误。

---

## 8.2 不同开源实现之间差异

由于没有官方公式，不同实现可能存在：

- 椭球参数差异；
- 边界判断差异；
- 逆转换策略差异。

通常：

```
厘米级 ~ 米级
```

---

## 8.3 eviltransform 精度

根据项目说明：

- `gcj2wgs()`：约 1~2 m；
- `gcj2wgs_exact()`：约亚米级。

---

# 9. GNSS 工程应用建议

GCJ-02 不应进入高精度定位计算流程。

错误：

```
GNSS
 |
GCJ02
 |
RTK error analysis
```

正确：

```
GNSS
 |
WGS84 / CGCS2000
 |
ECEF / ENU
 |
Position analysis
```

地图显示时：

```
WGS84
 |
GCJ02
 |
Map display
```

# 10. 总结

|问题|结论|
|-|-|
|是否有官方公开公式|没有|
|为什么没有|GCJ-02 用于地图数据扰动，不是公开测量标准|
|开源如何实现|通过逆向分析建立经验模型|
|计算量|正向 O(1)，逆向搜索需要更多计算|
|转换误差|坐标偏移百米级，实现差异米级|

`eviltransform` 代表了当前社区广泛使用的一类 GCJ-02 兼容实现，适合地图显示和 GIS 数据转换，但不适合作为 GNSS 高精度定位参考坐标。
