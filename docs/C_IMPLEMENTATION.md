# C implementation details of WGS84 / GCJ-02 transformation

## 1. Overview

This document describes the C implementation details of `c/transform.c` in this repository.

The implementation provides:

- `wgs2gcj()`: WGS-84 geographic coordinate to GCJ-02 coordinate conversion.
- `gcj2wgs()`: fast approximate GCJ-02 to WGS-84 conversion.
- `gcj2wgs_exact()`: higher accuracy inverse conversion using iterative search.
- `distance()`: spherical distance calculation.

GCJ-02 is not an official open geodetic reference frame like WGS-84 or CGCS2000. The implementation is an engineering reconstruction of the commonly used GCJ-02 transformation model.

---

## 2. Coordinate convention

All functions use:

```
latitude  : degrees
longitude : degrees
```

Example:

```c
double lat = 39.908823;
double lng = 116.397470;
```

Internal trigonometric calculations convert degrees to radians when required.

---

## 3. China boundary check

GCJ-02 transformation is normally applied only inside mainland China.

The implementation uses:

```c
lng >= 72.004 && lng <= 137.8347
lat >= 0.8293 && lat <= 55.8271
```

Outside this region the input coordinate is returned unchanged.

Reason:

- GCJ-02 offset is not intended for global use.
- Avoid unnecessary computation.

---

## 4. Forward transformation: WGS84 -> GCJ02

The main entry is:

```c
void wgs2gcj(
    double wgsLat,
    double wgsLng,
    double *gcjLat,
    double *gcjLng);
```

Processing flow:

```
WGS84 latitude/longitude
          |
          v
    calculate offset
          |
          v
    ellipsoid correction
          |
          v
       GCJ02
```

The conversion is:

```
gcjLat = wgsLat + dLat
gcjLng = wgsLng + dLng
```

where `dLat` and `dLng` are generated by the internal offset model.

---

## 5. Offset model

The internal function:

```c
transform(x, y, &dLat, &dLng)
```

uses:

```
x = longitude - 105
 y = latitude - 35
```

The model contains:

- polynomial terms
- square-root terms
- sinusoidal perturbations

Example components:

```
sin(6*x*pi)
sin(2*x*pi)
sin(y*pi)
sin(y*pi/3)
sin(y*pi/12)
```

The purpose is to reproduce the spatially smooth offset field of GCJ-02.

---

## 6. Ellipsoid correction

After calculating the raw offset, the implementation applies latitude and longitude scaling based on an Earth ellipsoid model.

Important parameters:

```c
EARTH_R = 6378137.0
```

and eccentricity squared:

```c
ee = 0.00669342162296594323
```

The correction considers:

- latitude-dependent radius change
- longitude scale change with latitude

This converts the abstract offset model into angular offsets in degrees.

---

## 7. Fast inverse transformation: GCJ02 -> WGS84

Function:

```c
void gcj2wgs(
    double gcjLat,
    double gcjLng,
    double *wgsLat,
    double *wgsLng);
```

Method:

```
WGS ~= GCJ - offset(GCJ)
```

Implementation:

```c
delta(gcjLat, gcjLng, &dLat, &dLng);

wgsLat = gcjLat - dLat;
wgsLng = gcjLng - dLng;
```

Advantages:

- very fast
- suitable for map display conversion

Limitation:

- it is an approximation because the offset should theoretically be evaluated at WGS84 coordinates.

Typical accuracy:

- around meter level.

---

## 8. Exact inverse transformation

Function:

```c
void gcj2wgs_exact(
    double gcjLat,
    double gcjLng,
    double *wgsLat,
    double *wgsLng);
```

The problem is:

```
GCJ = F(WGS)
```

The implementation solves:

```
Find WGS such that:

F(WGS) == target GCJ
```

using binary search.

Algorithm:

1. Create an initial search range around GCJ coordinate.
2. Take the middle point as WGS candidate.
3. Convert candidate WGS -> GCJ.
4. Compare with target GCJ.
5. Shrink latitude and longitude search ranges.
6. Repeat until convergence.

The search stops when:

```
abs(error_lat) < 1e-6 degree
abs(error_lng) < 1e-6 degree
```

Maximum iterations:

```
30
```

Advantages:

- much higher inverse accuracy
- deterministic convergence

Disadvantage:

- slower than `gcj2wgs()` because each iteration performs a forward conversion.

---

## 9. Numerical considerations

### Floating point

The implementation uses `double` because:

- latitude/longitude precision requirements are better than single precision.
- trigonometric functions require sufficient precision.

### Accuracy expectation

The transformation is not a surveying coordinate transformation.

Expected usage:

Good:

- map display
- GIS visualization
- location service compatibility

Not recommended:

- RTK baseline computation
- centimeter-level positioning
- geodetic adjustment

---

## 10. Recommended usage

For normal map display:

```
WGS84
  |
  | wgs2gcj
  v
GCJ02
```

For recovering WGS84 from GCJ02:

Fast:

```
gcj2wgs()
```

High accuracy:

```
gcj2wgs_exact()
```

---

## 11. Relationship with GNSS applications

GNSS receivers normally output:

```
WGS84 / CGCS2000-like coordinates
```

GCJ-02 should only be used at the presentation layer.

Do not use GCJ-02 coordinates for:

- RTK error statistics
- ENU conversion
- differential positioning
- satellite geometry calculation

because the intentional offset is at the hundreds-of-meters level.
